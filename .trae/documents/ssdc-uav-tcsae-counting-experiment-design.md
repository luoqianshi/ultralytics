### 2.3 已完成的 39 组改进实验结论（20260824 评估报告）
- 无一超过 +1.0pp；最佳 Focaler-CIoU +0.31（val）；
- 损失类最安全（权重迁移 100%）；结构类（BiFPN/FreqFusion全量/EMA骨干）迁移率低、性能降；
- **骨干 A2C2f 家族变体（Mona/MCA/MoCA/EMA/SCSA/FCM）全部负向 → 骨干不是瓶颈**；
- P2 小目标头不对症（小目标仅 9.7%）；SPDConv 优化崩溃（-7.30）。

### 2.4 Bad-case 误差分解（20260824-bad-case，测试集）
- 2,190 个 FN 中 **2,073 个（94.7%）是低分漏检**（模型框到了但置信度低，中位分 0.123），真正"完全没看到"仅 117 个（1.0%）；
- Oracle 上界：修复低分漏检 +4.58 AP50；背景抑制 +2.22；定位质量 AP75 0.61→0.88；
- 漏检率随尺度/密度单调上升：小苗 46% vs 大苗 9.5%；>12 株/图 27.1% vs 1~3 株 8.7%；
- **332 个高分背景 FP 目测为真实幼苗 → 疑似漏标**（数据侧瓶颈直接证据）；
- 重复 FP 仅 127 个（NMS 误删假说已被证伪）。

## 三、四个问题的最终结论（交付文档的核心内容）

### Q1 是否加载 COCO 预训练权重？→ 主协议统一**不加载**（from scratch）
1. **公平性**：结构改进会断裂预训练权重迁移，加载预训练会系统性偏袒损失类改进、惩罚结构类改进，消融结论不可信；
2. **自有证据**：数据集足够大（10,707 图/66,420 框），from-scratch 300ep 仅比预训练低 0.15pp；
3. **反例警示**：Focaler-CIoU 增益（+0.39）在 from-scratch 下归零——改进效应与协议交互，混用协议的实验无法互相比较；
4. **文献先例**：P14（改进YOLOv12n PCB缺陷，EI期刊）显式声明"统一超参+不用预训练权重"保证公平；
5. **论文写法**：方法/试验节加一张"预训练 vs from-scratch"协议对照表（数据已有：88.267 vs 88.121），一句话说明选择理由。

### Q2 选 s 还是 n？→ **s 尺寸为主基线**
1. 39 组改进语料全部在 s 上，消融深度与可比性最好；
2. s 与 n 精度差仅 0.39pp，但 s 的改进空间验证更充分；
3. 论文中必须写明选型理由（"综合检测与计数精度需求与计算成本，选 s；n 作为尺寸对照"）；
4. 现有 yolo12n 基线（87.88）直接作为尺寸消融行；若用户有 Jetson 等边缘设备，加分项：n 尺寸部署实测 FPS。

### Q3 骨干/颈部/头/损失改哪里？→ 骨干不动，四点改进覆盖四个层级
**骨干网络：明确不动**——6 组 A2C2f 家族变体全部负向，实证骨干特征提取不是瓶颈；论文可用一小段"骨干敏感性试验"反向论证改进选点的合理性。

四个改进点（每个挂一个 bad-case 实证问题，满足问题-方案一一映射）：
| # | 层级 | 改进点 | 针对问题（bad-case 证据） | 候选模块 |
|---|---|---|---|---|
| 1 | 损失函数 | 密集友好型损失（NWD 辅助损失，与 CIoU 加权融合） | 密集/小苗漏检率随重叠单调上升 16.4%→50%；IoU 类损失对小框不敏感 | NWD（仓库已有 re0 训练脚本 `train_yolov12-NWD_ssdc-uav_re0.py`，需补完训练与测试） |
| 2 | 颈部上采样 | 内容感知上采样替换最近邻 | 小苗漏检率 46% 是大苗 4.8 倍，上采样丢细节 | CARAFE（P17 学报先例，需实现）或 DySample（仓库已有，需 from-scratch 重验） |
| 3 | 检测头 | 任务对齐/共享卷积轻量化头 | 94.7% 漏检是低分漏检（打分校准问题）；计数需要一致的打分 | DyHead（仓库已有，预训练下无效，需 from-scratch 重验）或共享卷积头（P17 LSCSBD） |
| 4 | 后处理 | Soft-NMS/DIoU-NMS 去重 | 密集场景打分抑制；重复 FP 影响计数准确性；NMS 扫描已证 iou 0.5~0.6 有 +0.36~0.51 免费收益 | Soft-NMS（内部报告 R2 推荐，先重测现有 best.pt 即可，零训练成本） |

数据侧（不计为改进点，计入数据集建设贡献）：**标注审计**——复核 332 个疑似漏标（`traework/20260824-bad-case/data/audit_high_bgfp.csv`）+ 抽检低分漏检边界苗，修订后重建干净测试子集，作为"数据质量提升"叙事。

备选（若 ①-④ 增益仍在噪声带内）：特征知识蒸馏 CWD/MGD（教师 yolo12l/x，内部报告预期 +0.8~1.5，杠杆最高但训练成本大）。

### Q4 如何判断瓶颈在数据还是算法？→ 五步判别框架 + 本案结论
1. **误差分解（Oracle 分析）**：FN/FP 分类 → 模拟修复后的 AP 增益（本案已做：低分漏检 +4.58 为最大上界）；
2. **架构敏感性试验**：统一协议换 N 种架构变体，若全在噪声带内 → 架构非瓶颈（本案 39 组 < +1.0pp，噪声带 0.16pp → 骨干/颈部架构非瓶颈）；
3. **标注审计实验**：人工复核可疑 FP/FN → 修订标注重训，mAP 显著上升 = 数据瓶颈（本案已发现 332 疑似漏标，待执行）；
4. **数据规模实验**：25%/50%/75% 子集训练看 scaling 趋势，未饱和 = 数据量瓶颈；
5. **人类上限/交叉验证**：小样本人工复核上限或公开数据集交叉验证。

**本案结论**：瓶颈主要在**数据侧（标注质量 + 难样本置信度）与后处理**，而非骨干架构。依据即上述 2.3/2.4 证据。

### 实验协议（论文"试验环境与参数设置"节）
- 统一 from-scratch、imgsz 640、SGD、300 epochs（from-scratch 需更长收敛，已有 300ep 证据仍在缓升）；
- 关键配置（基线 + 最终组合）**3 个随机种子**，报均值±标准差，正面回应显著性质疑；
- 评价指标：检测 P/R/mAP50/mAP50-95 + 计数 R²/MAE/RMSE + Params/GFLOPs/FPS 全表呈现（2026 年标配）；
- 计数评价方法（TPH-YOLO 范式）：tile 级（每切片检测框数 vs GT 框数）+ 原始大图级（30 张测试大图、8,540 株人工真值），线性回归报 R²/MAE；
- 对比模型：yolov8s / yolo11s / yolo26s（from-scratch 版权重已有）+ RT-DETR（需新跑）+ 可选 Faster R-CNN（学报标配两阶段代表）；
- 消融矩阵：基线 + 4 单模块 + 关键两两组合 + 全组合 ≈ 9~11 组，√/× 矩阵呈现，分析模块间互补/抑制。
