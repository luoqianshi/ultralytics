SSDC-UAV YOLO12s Baseline Bad Case 全面分析报告

生成日期：2026-08-24 ｜ 分析对象：YOLO12s-baseline（150 epoch，COCO 预训练）｜ 测试集：SSDC-UAV test split（1703 张切片 / 11263 个真值实例）
预测来源：runs/ssdc_uav_test/size-s-base/yolo12s-baseline_ssdc_uav_test_exp01/predictions.json（97,356 条，conf=0.001，NMS iou=0.7）
核心结论（TL;DR）
  1. Recall 瓶颈的本质是「置信度被压低」，不是「没检测到」。2190 个漏检中，94.7%（2073 个）的苗其实已被模型框出（IoU≥0.5），只是置信度低于 F1 最优阈值 0.378；真正完全没被任何预测覆盖的苗仅 117 个（1.0%）。
  2. 「密集场景 NMS 误删是 FN 主源」的假说被三条独立证据证伪（第 6 节）：GT-GT 结构性重叠极小（IoU≥0.7 的仅占 0.036%）；漏检几乎全是低分而非消失；实测放松 NMS 指标反而全面变差。真正机制是密集/重叠/小目标场景下模型打分受抑制。
  3. 免费收益：NMS iou 从默认 0.7 调到 0.5~0.6，mAP50 +0.36~0.51 点、Recall +0.9~1.7 点、Precision 不降；而 imgsz=960 推理与 TTA 均无收益（负收益）。
  4. 最大可回收收益在「难样本判别力」：Oracle 模拟显示，若 2073 个低分漏检被打分修复，AP50 从 0.8797 → 0.9255（+4.58 点）、操作点 Recall 0.806 → 0.990。这些样本置信度中位数仅 0.123，不是阈值微调能解决的。
  5. 第二收益在定位质量：3347 个 TP 框 IoU 落在 [0.5, 0.75)，完美定位的 AP75 上界为 0.8797（当前 0.6075，+27.2 点），这是 mAP50-95（0.556）偏低的主因。
  6. 标注噪声值得审计：332 个高分背景 FP（score≥0.5）疑似真实漏标苗；在噪声地板 σ≈0.10 mAP50 的背景下，清洗标注的边际收益可能大于继续改模型。

排名Oracle 修复修复对象ΔAP50Δ 操作点对应改进方向

3O4 完美定位（以 AP75 计）3,347 个 IoU∈[0.5,0.75) 的 TP AP75 +27.2 → 0.8797— 回归损失改进（PIoU2/Focaler-CIoU 已验证微效，可叠加）——主要拉升 mAP75/mAP50-95

归因结论
Recall 的瓶颈 = 难样本置信度不足（O1，上界 +4.6 点）；Precision 的瓶颈 = 背景 FP（O3，上界 +2.2 点，其中混有标注噪声）；mAP75/mAP50-95 的瓶颈 = 定位质量（O4）。三者正交。对照你的改进有效性标准（mAP50≥+1.0、Recall 优先）：只有 O1 方向的空间足够大——只要捕获其上界的约 1/4 即可达标；O2 类后处理与单纯调阈值注定不达标。

6. B 层：NMS 假说证据链 —— 假说被证伪

待检验假说（来自 2026-08-24 上午评估）：「数据集 6.6 株/图密集重叠，NMS 误删是 FN 主源，Recall 因此被封顶」。三条独立证据：

证据 1：GT-GT 结构性重叠上限

若两株苗的 GT 框 IoU ≥ NMS 阈值，则即使完美检测，NMS 也必然删掉其一（结构性漏检）。实测：

GT-GT 最大 IoU 阈值≥0.5≥0.6≥0.7（=默认NMS）≥0.8≥0.9
涉及的 GT 占比0.74%（83 株）0.25%0.036%（4 株）0.018%0%

在默认 NMS iou=0.7 下，结构性误删的理论上界仅 0.036%——而实际 FN 高达 19.4%。NMS 误删解释不了两个数量级之外的漏检。

证据 2：FN 解剖（post-NMS 视角）

predictions.json 是 NMS 之后的输出。2190 个 FN 中，2073 个（94.7%）在文件里存在 IoU≥0.5 的存活预测——它们没被 NMS 删掉，而是活到了输出、只是分数低。真正「疑似被 NMS 删除/从未检出」的仅 117 个（5.3%）。

证据 3：NMS 阈值实测扫描（决定性）

证伪结论
若「NMS 误删」是 FN 主源，则放松 NMS（iou 调大）应当提升 Recall 与 mAP。实测完全相反：放松 NMS 指标单调恶化（大量重复/虚警框存活，挤占 Precision 并拖垮 AP）；收紧到 0.5~0.6 反而免费获得 +0.4~0.5 mAP50 与 +0.9~1.7 Recall。说明本数据集的相邻框多为「重复/虚警」而非「相邻真苗」。
修正后的机制解释：密集/重叠场景 → 特征干扰 → 模型对真苗的置信度被压低（而非框被删掉）→ 低分漏检。改进应瞄准「打分质量」，而不是 NMS 策略或 soft-NMS 类后处理。

8. 标注噪声嫌疑审计

  • 高分背景 FP：score≥0.5 且与所有 GT 的 IoU<0.1 的预测共 332 条（全量 572 条 bgFP 已按分数降序存至 data/audit_high_bgfp.csv）。抽看 Top 样例（7.3 节），红框内目测为真实幼苗——高度疑似漏标。
  • 双向影响：漏标同时压低 Precision（真苗被判 FP）与 Recall 的测量可信度（部分「低分 FN」可能对应边界模糊、标注口径不一的苗）。
  • 成本收益：复核 332 个框约 1~2 小时人工；在此前标定的噪声地板 σ≈0.10 mAP50（2σ≈0.2）背景下，清洗标注能同步抬高 P、R 的测量值与真实值——边际收益可能超过再跑若干组结构实验，且是后续一切改进评估可信度的前提。

9. 改进优先级清单（对齐标准：mAP50≥+1.0、P/R 不同时降、Recall 优先）

P0 立即可用（零训练成本）

  • NMS iou 0.7 → 0.5（计数/Recall 优先场景）或 0.6（mAP 优先场景）：mAP50 +0.36~0.51，Recall +0.9~1.7，Precision 不降。注意 ±0.2 以内接近噪声地板，建议固定 iou=0.5 复测 2~3 个种子确认。
  • 部署阈值按操作点表换档（第 2 节），不要沿用默认 0.25 或盲目用 F1 最优点。

单独达不到 +1.0 标准，但应作为后续一切实验的新基线设置。

P1 主攻方向：难样本判别力 / 置信度质量（理论空间 +4.6 mAP50，Recall +18）

  1. 损失层：质量感知置信度目标。2073 个低分漏检的中位分仅 0.123，说明 cls/conf 分支对难样本系统性低估。方向：VarifocalLoss / QualityFocalLoss 类（IoU 感知的软置信度目标），让定位准的难样本获得合理高分；与你已验证微效的 Focaler 系列不冲突、可叠加。
  2. 数据层：小目标与密集场景增广。COCO small 漏检率 46%（大苗的 4.8 倍）：copy-paste 增广（把苗贴入密集区）、小目标过采样、提高训练分辨率（640→896/960，训练放大而非推理放大——后者已证无效）。
  3. 难例挖掘闭环：以本次 2073 个低分 FN 为「难例种子」（data/gt_cases.csv 筛 status=FN_lowScore），回查训练集中同类形态（小株/重叠/低对比），定向增补或加权。
  4. 不建议再试：P2 检测头（极小目标口径仅 0.24%，不对症）、soft-NMS/提高 NMS iou（已证伪）、推理 imgsz 放大与 TTA（已证无效）、去重后处理（dupFP 仅 127 条）。

P2 次要方向：定位质量（AP75 上界 +27，主拉 mAP75/mAP50-95）

3347 个 TP 框 IoU 落在 [0.5, 0.75)。PIoU2、Focaler-CIoU 已验证微效且不打断预训练权重迁移，可保留并与 P1 方向叠加；但单独不足以达到 mAP50+1.0 标准，定位到的是 mAP50-95（0.556）而非 mAP50。

P3 地基工程：标注质量审计（建议先于下一轮实验）

复核 data/audit_high_bgfp.csv 中 332 个高分背景 FP + 抽检低分 FN 中的边界模糊苗。清洗后重测 baseline，获得可信的新基准线——否则后续 ±0.5 以内的改进都无法与标注噪声区分。

10.2 方法与口径

  • 匹配：预测按分数降序与 GT 贪心匹配（每 GT 至多被一个预测占有），IoU 阈值 0.5（主口径）与 0.75（定位口径）；AP 为 101 点插值（COCO 风格），复算 AP50=0.8797 对官方 0.8827。
  • 操作点：F1 最优 t*=0.378；FP 分类按 max IoU（≥0.5→重复；[0.1,0.5)→定位；<0.1→背景）。
  • Oracle：O1 将低分匹配预测分数抬至 t* 之上重算；O2/O3 删除对应预测重算；O4 将 IoU0.5 匹配视为 0.75 匹配重算 AP75——均为上界，实际方法只能逼近。
  • NMS 扫描：同一 best.pt 在测试集以 iou∈{0.4,...,0.95} 重跑 val（conf=0.001, imgsz=640, batch=16），结果见 data/nms_sweep.csv。
  • 复现：conda run -n ultralytics_new python scripts/01_decompose.py（其余脚本同）。
