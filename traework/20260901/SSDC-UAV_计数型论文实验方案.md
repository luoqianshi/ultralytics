## 一、总体战略（一页摘要）

**一句话**：瓶颈不在骨干架构，而在**数据侧（标注质量+难样本置信度）与后处理**；论文应以 s 尺寸 YOLO12 为基线、统一 from-scratch 协议，围绕"密集漏检、小苗漏检、打分校准、重复框"四个实证问题做四层级改进，并用**计数指标（R²/MAE）作为差异化贡献**讲甘蔗幼苗精准计数的农业故事。

| 决策项 | 结论 | 一句话理由 |
|---|---|---|
| COCO 预训练 | **主协议不加载**（统一 from-scratch） | 结构改进断裂权重迁移，混用协议不可比；数据集足够大，从零仅低 0.15pp |
| 模型尺寸 | **s 为主基线，n 作对照** | 39 组语料全在 s；s 与 n 仅差 0.39pp；论文写明选型理由 |
| 骨干网络 | **不动** | 6 组 A2C2f 变体全部负向，实证骨干非瓶颈 |
| 颈部 | 内容感知上采样（CARAFE/DySample） | 小苗漏检率 46% 是大苗 4.8 倍 |
| 检测头 | 任务对齐/共享卷积头 | 94.7% 漏检是低分漏检（打分问题） |
| 损失函数 | NWD 辅助损失（与 CIoU 融合） | 密集重叠场景漏检率 16.4%→50% |
| 后处理 | Soft-NMS 去重 | NMS 扫描已证 +0.36~0.51pp 免费收益；重复框直接影响计数 |
| 数据侧 | 标注审计（332 个疑似漏标） | 计入数据集建设贡献，不作为改进点 |
| 差异化贡献 | **计数 R²/MAE 双层级评价** | 基线计数 R²=0.876、系统性少数 6.5%，改进空间明确 |

## 二、问题 1：是否加载 COCO 预训练权重？

### 结论：主实验协议统一**不加载**（from scratch），并附一张协议对照表说明理由。

### 证据链

| 证据 | 数值（测试集 mAP50，%） | 含义 |
|---|---|---|
| YOLOv12s + COCO 预训练 150ep | 88.267 | 预训练基线 |
| YOLOv12s from-scratch 150ep | 87.933 | 从零仅低 0.33pp |
| YOLOv12s from-scratch 300ep | 88.121 | 从零仅低 0.15pp |
| Focaler-CIoU（预训练协议） | 88.656（+0.39） | 历史最佳"改进" |
| Focaler-CIoU（from-scratch 协议） | 87.932（**+0.00**） | 改进效应与协议交互！ |

### 论证逻辑（写进论文的话术）

1. **公平性**：结构性改进（换上采样/换头/改骨干）会断裂 COCO 预训练权重的迁移——加载预训练会系统性偏袒"损失类/后处理类"改进、惩罚"结构类"改进，消融结论不可信。统一 from-scratch 后所有模块站在同一起跑线。
2. **数据充分性**：SSDC-UAV 训练集 10,707 张图、66,420 个标注框，from-scratch 300ep 与预训练差距仅 0.15pp，说明数据集规模足以支撑从零收敛，无需借 COCO 先验。
3. **反例警示**：Focaler-CIoU 的 +0.39pp 增益在 from-scratch 协议下归零——混用两种协议的实验结果互相不可比，这是历史 39 组实验的主要方法学隐患。
4. **文献先例**：《改进YOLOv12n的PCB缺陷检测》（电子测量与仪器学报 2026）显式声明"统一超参+不使用预训练权重"以保证对比公平，该做法被审稿体系接受。
5. **落地动作**：论文"试验环境与参数设置"节放一张两行协议对照表（88.267 vs 88.121），一句话声明："为保证结构改进与损失改进的对比公平性，本文所有实验统一采用从零训练协议"。

> 注：预训练权重并非"错误"，而是"不可混用"。若审稿人质疑，可补充说明预训练版作为工程部署备选（收敛更快），但论文主实验保持单一协议。

## 三、问题 2：选 s 还是 n 尺寸？

### 结论：**s 尺寸为主基线**，n 尺寸作为尺寸消融对照行；若有边缘设备，n 尺寸部署实测作为加分项。

### 证据链（测试集）

| 模型 | Params (M) | GFLOPs | mAP50 (%) | 备注 |
|---|---|---|---|---|
| YOLOv12s（预训练 150ep） | 9.25 | 21.52 | 88.267 | 主基线 |
| YOLOv12n（预训练 250ep） | 2.57 | 6.48 | 87.880 | 仅低 0.39pp |

### 论证逻辑

1. **实验语料连续性**：已完成的 39 组改进实验全部在 s 尺寸，消融深度与模块行为认知（哪些有效、哪些失败）都建立在 s 上，换 n 等于推倒重来。
2. **精度差距小**：s 与 n 仅差 0.39pp，说明该任务对容量不敏感——这本身是论文里"尺寸选型"小节的实证素材。
3. **论文写法**：方法节必须写明选型理由（期刊审查点）："综合考虑检测与计数精度需求及计算成本，选用 s 尺寸作为基线；同时给出 n 尺寸对照实验以验证方法的尺寸鲁棒性"。
4. **加分项**：若后续有 Jetson 等边缘设备，用 n 尺寸 + 最终改进做部署实测（FPS），补齐《农业工程学报》偏好的落地叙事——注意部署实验用 n、主实验用 s，两者在论文中各自交代清楚，不冲突。

## 四、问题 3：骨干/颈部/检测头/损失函数，改哪里？

### 4.1 骨干网络：明确不动（用反向证据写成论文亮点）

已完成的 6 组骨干/主干级实验**全部负向**：

| 骨干变体 | 测试集 mAP50 (%) | vs 基线 88.267 |
|---|---|---|
| A2C2f_Mona | 88.153 | -0.11 |
| A2C2f_MCA（300ep） | 88.064 | -0.20 |
| EMA | 88.028 | -0.24 |
| A2C2f_EMA | 88.012 | -0.26 |
| A2C2f_SCSA_CBAM | 86.848 | -1.42 |
| A2C2f_FCM（300ep） | 87.550 | -0.72 |
| Mona（全替换） | 87.152 | -1.12 |
| MoCA | 86.587 | -1.68 |

**结论**：YOLO12 的 A2 区域注意力骨干对该任务已接近饱和，骨干特征提取不是瓶颈。论文中可用一小段"骨干敏感性试验"反向论证改进选点的合理性——这是审稿人喜欢看到的"为什么改这里而不改那里"的实证回答。

### 4.2 四个改进点（每点挂一个 bad-case 实证问题）

| # | 层级 | 改进点 | 针对问题（实证） | 候选模块 | 实现状态 |
|---|---|---|---|---|---|
| 1 | 损失函数 | 密集友好型辅助损失 | 漏检率随重叠/密度单调上升 16.4%→50%；IoU 类损失对小框/密框不敏感 | **NWD**（归一化 Wasserstein 距离，与 CIoU 加权融合） | 训练脚本已有（`train_yolov12-NWD_ssdc-uav_re0.py`），需补完训练与测试 |
| 2 | 颈部上采样 | 内容感知上采样替换最近邻 | 小苗漏检率 46.0% 是大苗（9.5%）的 4.8 倍；最近邻上采样丢失小目标细节 | **CARAFE**（学报先例 P17）或 **DySample**（仓库已有） | CARAFE 需实现（放 `ultralytics/nn/AddModules/`）；DySample 需 from-scratch 重验 |
| 3 | 检测头 | 任务对齐/共享卷积轻量化头 | 2,190 个漏检中 2,073 个（94.7%）是低分漏检——模型"看到了但打不出分"，属打分校准问题；计数任务需要跨图一致的打分 | **DyHead**（仓库已有）或共享卷积头（P17 LSCSBD 范式） | DyHead 需 from-scratch 重验；共享卷积头需实现 |
| 4 | 后处理 | Soft-NMS/DIoU-NMS 去重 | 密集场景模型打分被抑制（NMS 扫描：iou 0.5~0.6 免费 +0.36~0.51pp、Recall +0.9~1.7pp）；127 个重复框直接污染计数 | **Soft-NMS**（先重测现有 best.pt，零训练成本） | 待执行 |

**数据侧（不计为改进点，计入数据集建设贡献）**：标注审计——复核 332 个高分疑似漏标（`traework/20260824-bad-case/data/audit_high_bgfp.csv`）+ 抽检低分漏检边界苗，修订后重建干净测试子集。这在论文中写成数据集质量保障环节，呼应《农业工程学报》对自建数据集可信度的要求。

**备选高杠杆项**（若 ①-④ 增益仍落在噪声带内）：特征知识蒸馏（CWD/MGD，教师 yolo12l/x）——内部评估预期 +0.8~1.5pp，是唯一可能大幅突破噪声带 0.16pp 的方向，但训练成本大，作为预案。

### 4.3 为什么是这四个：问题-方案一一映射（论文方法章的骨架）

```
田间问题                     基线缺陷                技术方案              预期效果
密集分布+重叠 → 漏检率50%  → IoU损失对小密框不敏感 → NWD辅助损失        → 密集场景Recall↑
小苗细节丢失  → 漏检率46%   → 最近邻上采样丢细节   → 内容感知上采样      → 小目标检出↑
打分不一致    → 94.7%低分漏检→ 静态检测头打分校准差 → 任务对齐/共享卷积头 → 置信度校准、计数一致性
重复框+误删   → 计数偏差     → 硬NMS               → Soft-NMS           → 计数准确性↑
```

### 4.4 历史教训清单（避坑，全部来自 39 组实验）

- 双改进组合出现负协同（Focaler-CIoU+DySample 88.279 < 单改进 88.656）——组合必须过消融，不能想当然叠加；
- 拓扑重写型（BiFPN 88.105、FreqFusion 全量 87.623）迁移率低、性能降——不做颈部整体重写；
- P2 高分辨率头不对症（小目标仅 9.7%）且 GFLOPs +32%——不加 P2；
- SPDConv 导致优化崩溃（-7.30）——不用；
- 所有结论以 from-scratch 统一协议重验后才可写进论文。

## 五、问题 4：如何判断瓶颈在数据还是算法？

### 5.1 五步判别框架（通用方法论，可写进论文讨论节）

1. **误差分解（Oracle 分析）**：把 FN/FP 拆成可操作的类别，模拟"若修复这类错误，AP 能涨多少"，找到增益最大的错误类型；
2. **架构敏感性试验**：统一协议下替换 N 种架构变体——若全部落在噪声带内，说明架构不是瓶颈；
3. **标注审计实验**：人工复核可疑 FP/FN，修订标注重训——mAP 显著上升 = 标注质量瓶颈；
4. **数据规模实验**：用 25%/50%/75% 子集训练看 scaling 趋势——未饱和 = 数据量瓶颈；
5. **人类上限/交叉验证**：小样本人工复核上限或公开数据集交叉验证，界定"还能涨多少"。

### 5.2 本案已完成的判别（步骤 1、2 已做，3 待做）

**误差分解结果**（测试集，11,263 个 GT）：

| 发现 | 数值 | 指向 |
|---|---|---|
| 低分漏检占全部漏检 | 2,073/2,190 = **94.7%** | 打分/难样本问题，不是"看不见" |
| 完全未定位漏检 | 仅 6 个（0.05%） | 特征提取基本够用 → 骨干非瓶颈 |
| 修复低分漏检的 Oracle 上界 | AP50 0.880→0.926（**+4.58pp**） | 最大杠杆在打分校准 |
| 背景抑制上界 | +2.22pp | 其中 332 个高分 FP 疑似漏标 → 数据侧 |
| 定位质量上界 | AP75 0.607→0.880 | 回归质量是 mAP50-95 的主要约束 |
| 漏检率×尺度 | 小苗 46% vs 大苗 9.5% | 上采样/小目标通路 |
| 漏检率×密度 | 16.4%→50%（随重叠单调上升） | 密集友好损失/后处理 |

**架构敏感性结果**：39 组架构/模块变体，最好 +0.39pp，全部 < +1.0pp；双基线噪声带 0.16pp → **架构改动收益已逼近统计噪声下限**。

### 5.3 本案结论

> 瓶颈主要在**数据侧（标注质量 + 难样本置信度）与后处理策略**，而非骨干架构。
> 依据：①39 组架构变体全部落在噪声带附近；②94.7% 的漏检是"框出来了但分数低"；③332 个高分背景误检目测为真实幼苗（疑似漏标）；④漏检率与物理因素（尺度/密度）强相关，属任务固有难度，需靠数据质量与针对性损失/后处理缓解，而非更强的通用特征提取。

## 六、计数维度：基线快评结果（本次新产出）

基于已有测试集预测（YOLOv12s-baseline，1,703 张切片、11,263 个 GT），按不同置信度操作点计算 tile 级计数指标：

| 操作点 | conf | 预测总数 | GT 总数 | R²（拟合） | MAE（株/切片） | RMSE | 斜率 |
|---|---|---|---|---|---|---|---|
| F1 最优点 | 0.378 | 10,535 | 11,263 | **0.876** | 1.09 | 1.66 | 0.80 |
| Recall 优先（P≥0.80） | 0.257 | 11,981 | 11,263 | 0.850 | 1.12 | 1.62 | 0.94 |
| Precision 优先（P≥0.85） | 0.355 | 10,776 | 11,263 | 0.872 | 1.06 | 1.61 | 0.83 |
| 高置信 | 0.500 | 9,226 | 11,263 | 0.871 | 1.46 | 2.25 | 0.68 |

**解读**：
1. 基线计数 R²=0.876、斜率 0.80——**系统性少数约 6.5%**（10,535 vs 11,263），与"94.7% 低分漏检"互相印证：漏检直接转化为计数偏差；
2. 降低阈值可把斜率拉回 0.94 但 R² 下降——说明"计数准确性"与"检测打分质量"是同一个问题的两面，支持改进点 ③（检测头打分校准）的必要性；
3. 这组数字是论文计数叙事的起点：改进后报告 R²/MAE 的提升，与 mAP 提升互相印证（TPH-YOLO 范式）。
4. 待执行：原始大图级计数（30 张测试大图、8,540 株人工真值），对标田间实际计数需求。

## 七、实验协议与实验矩阵

### 7.1 统一协议（论文"试验环境与参数设置"节）

- 训练协议：**统一 from-scratch**，imgsz 640，SGD，300 epochs（from-scratch 需更长收敛，已有证据 300ep 仍在缓升）；
- 显著性：基线与最终组合 **3 个随机种子**，报均值±标准差；
- 评价指标：检测 P/R/mAP50/mAP50-95 + 计数 R²/MAE/RMSE + Params/GFLOPs/FPS 全表呈现；
- 计数评价（两级）：
  - tile 级：每切片检测框数 vs GT 框数（1,703 切片），线性回归报 R²/MAE/RMSE；
  - 原始大图级：30 张测试大图聚合计数 vs 人工真值（8,540 株），报 R²/MAE；
- 公平性声明：统一超参、统一协议、不用预训练权重（附协议对照表）。
